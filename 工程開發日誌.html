WebView2 黑畫面 / 狂重啟修復（argparse 參數解析）

Critical Fix Runtime Stability Release
根因分析
  • 主要原因：Player 啟動 WebViewPlayer 時使用 --browser-args "--renderer-process-limit=4"。由於參數值本身以 -- 開頭，會被 argparse 視為新選項，導致 --browser-args 變成「沒有值」。
  • 外部症狀：WebViewPlayer 行程啟動後立即退出，Player 端持續出現「Window not found / No webviewplayer.exe processes found」，進而反覆重啟 WebView 視窗，最終造成 Web 與影片區域黑畫面。
修正內容
  • player.py：將傳遞格式改為 --browser-args=...（同一個 token），避免 argparse 把值誤判為新選項。
  • player.py：對 webview_browser_args 做基本清理；若收到多個 token，暫以第一個 token 為準並寫入提示 log，防止啟動命令被拆壞。
  • webview_player.py：加入向下相容轉換。若收到舊格式 --browser-args --xxx，啟動前自動重寫為 --browser-args=--xxx 再交給 argparse。
相關整合與打包
  • WebAdmin：新增 webview_host_mode 開關（讀取/儲存 config）。
  • build_release.py：補上必要元件缺失檢查（缺件直接 fail），並統一輸出啟動腳本：run_admin.bat、run_player.bat、run_webserver.bat。
  • setup_script.iss：檢查與修正捷徑/啟動項目，重新編譯安裝包。
驗證結果
  • python -m py_compile player.py webview_player.py 通過。
  • venv\Scripts\python.exe build_release.py 成功。
  • ISCC setup_script.iss 成功，產生新版 build\ScreenSplitter_Setup.exe。
參數修正摘要
舊：--browser-args "--renderer-process-limit=4"
新：--browser-args=--renderer-process-limit=4

穩定性 影片管線 播放策略

  • QMediaPlayer 崩潰：正式版 Player.exe 觸發 ffmpegmediaplugin.dll 0xc0000005（Access Violation），非單純 GPU 開關可解。
  • QWebEngine 內播 MP4 黑畫面：GPU off 時仍黑，推測為 codec 支援不足或解碼鏈無法啟動。
  • 多路 4K 壓力：同場景 4K+4K+2K 影片在 WebView2 易卡死，msedgewebview2 進程過多且吃資源。
決策與方向
  • Web：維持外部 WebView2（use_edge=true），固定 profile 路徑，避免重建。
  • Video：改用 VLC 外部播放，硬體解碼開啟，循環播放，避免 QtMultimedia/QtWebEngine 崩潰風險。
  • 視窗重用：以 Tag 固定重用視窗（VLC_S{scene}_Z{zone}），場景切換只做隱藏/顯示，不重建。
打包與部署
  • VLC 路徑規範：統一放在 D:\ScreenSplitter\VLC\vlc.exe。
  • build_release.py：打包時自動複製 ./VLC 到輸出根目錄，確保正式版可找到 VLC。
下載注意
  • ZIP 下載失敗：出現「找不到中央目錄」代表 ZIP 不完整（常見於代理或斷線）。
  • 建議方式：改用 PowerShell BITS 下載 + ZIP 檢查（PK 開頭）再解壓。

CRITICAL: 系統渲染架構重構與崩潰修復

Critical Fix Architecture Stability
🛑 事件描述 (Incident)

系統在長時間運行或高負載下出現嚴重不穩定，Event Viewer 顯示大量 0xc0000005 (Access Violation) 與 0xe0000008 (Kernel Exception) 錯誤。導致畫面卡頓、白屏，且因 Watchdog 機制導致無法正常關閉。

🔧 診斷分析 (Diagnosis)
  • 0xc0000005: GPU 硬體加速與 QtWebEngine 發生記憶體衝突。
  • 0xe0000008: Windows Defender/防毒軟體觸發 Renderer Code Integrity 檢查，強制殺死渲染子程序。
  • Zombie Process: cmd.exe (Watchdog) 在程式崩潰後無限重啟，導致 UI 上的「關閉」按鈕無效。
✅ 解決方案 (Resolution) - v7:30 Stable
  • 實作「終極安全模式」 (Ultimate Safe Mode): 完全棄用 GPU，改採 CPU 軟體渲染。
  • Flag 調整: --disable-gpu --disable-opengl --disable-features=RendererCodeIntegrity
  • 實作 Force Quit: 在 Python 層加入 psutil 邏輯，主動搜尋並終結父程序 (Parent CMD)，解決無限重啟迴圈。
player.py (Flags update)
os.environ["QTWEBENGINE_CHROMIUM_FLAGS"] = "--disable-gpu --disable-features=RendererCodeIntegrity,FlashDeprecationWarning --process-per-site"
