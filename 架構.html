Screen Splitter Player (V4) - 系統架構說明

系統概觀 (System Overview)

本系統基於 Python 3.10+ 與 PySide6 (Qt) 開發，核心功能為多視窗分割管理與外部程式嵌入。 不同於傳統的 Qt 應用，Player V4 大量使用了 Windows API (Win32GUI/Win32Process) 來強制管理外部視窗 (VLC, Chrome, WebView2, Unity Games 等)， 使其看起來像是單一整合的應用程式。

  • 核心語言: Python 3.10+
  • GUI 框架: PySide6 (Qt 6.x)
  • 視窗管理: Win32 API (pywin32) + psutil
  • 渲染引擎: QtWebEngine (內建) / Edge WebView2 (外部 Host) / VLC (外部)

WebView2 Host Mode 架構

為了解決多個 WebView 實例導致的記憶體暴增問題，V4 引入了 Host Mode。 所有 WebView 視窗由單一外部進程 (WebViewPlayer.exe --host) 統一管理，透過 JSON 檔案進行通訊。

sequenceDiagram participant Player as Player.py (Main) participant Host as WebViewPlayer.exe (Host) participant File as webview_cmd.json participant Status as webview_status.json Player->>Player: load_scene 分析 Zone Player->>Player: 發現多個 Web Zone opt Host 未啟動 Player->>Host: 啟動 Host Process (--host) end loop Enforce Loop (500ms) Player->>File: 寫入指令 (Upsert: URL, Rect, Tag) Host->>File: 讀取指令 & 執行 Host->>Host: 建立/更新 WebView 視窗 Host->>Status:回報視窗 Handle (HWND) Player->>Status: 讀取 HWND Player->>Player: 綁定 HWND 進行 Z-Order 管理 end
優勢: 節省 50-70% 記憶體，避免瀏覽器進程風暴。
容錯: 若 Host 當機，Player 會自動重啟 Host 或降級為獨立視窗模式。

關鍵視窗查找邏輯 (Window Finding Logic)

這是系統最複雜的部分，位於 find_main_window_for_exe。為了確保抓到正確的視窗，系統使用了多層過濾機制。

# 計分標準 (Scoring):
+50 視窗可見 (Visible)

+20 標題非空 (Has Title)
+15 尺寸合理 (>100px)
+10 有標題列 (Caption)

故障排除與自我修復 (Self-Healing)

  • Re-entry Guard: enforce_loop 具備重入保護，防止上一次迴圈未結束就開始下一次，造成 CPU 100%。
  • 僵屍進程清理: cleanup_rogue_processes 會定期掃描並強制關閉不屬於當前場景的外部 Helper 進程。
  • 樣式剝離冷卻: strip_borders 每秒最多執行一次，防止與 Chrome/VLC 的原生樣式邏輯衝突（閃爍問題）。
  • VLC 復原: 若 VLC 崩潰，Player 會檢測到 PID 消失並重新啟動它。

建議補強 1：Process Boundary 與責任邊界

目前文件已描述主要流程，但還缺「誰負責什麼」的清楚邊界圖。建議補上以下圖，避免維運時把 Player/Host 的職責混在一起。

flowchart LR WA[WebAdmin / admin.py] -->|NEXT JUMP PAUSE| IPCA[ipc_cmd.txt] IPCA --> P[Player.exe] P -->|status write| IPCB[ipc_status.json] P -->|upsert/close commands| WVC[webview_cmd.json] WVH[WebViewPlayer.exe --host] -->|window status| WVS[webview_status.json] WVC --> WVH WVS --> P P -->|launch/manage| VLC[VLC.exe] P -->|launch/manage| APP[External EXE Apps] P -->|find/move/hide| WIN32[Win32 API + psutil] WIN32 --> VLC WIN32 --> APP WIN32 --> WVH
  • Player: 排程、分區計算、視窗管控、故障恢復決策。
  • WebView Host: 多視窗建立/更新/隱藏（不負責排程）。
  • WebAdmin: 只送控制命令，不直接操作 HWND。

建議補強 2：IPC 檔案契約（Schema）

建議把 IPC 檔案視為正式介面，文件化欄位、寫入端、讀取端與時序，減少跨程式改動風險。

File Writer Reader Payload Notes
ipc_cmd.txt WebAdmin Player NEXT / PREV / JUMP n / PAUSE / RESUME / EXIT 單一命令，Player 讀完即刪。
ipc_status.json Player WebAdmin scene_idx, paused, remaining, total, timestamp 供 UI 狀態顯示。
webview_cmd.json Player WebView Host Array of {op,tag,url,x,y,w,h,show} op=upsert/hide/close/exit。
webview_status.json WebView Host Player {pid, windows[], ts} 供 Player 做健康檢查與恢復判斷。

建議補強 3：DPI 與座標轉換鏈

這個專案最容易閃爍的點是 Logical/Physical 混用。建議把座標鏈固定畫出來，並附上容差策略。

flowchart TD Z[Zone _rect from config] --> L[Logical rect: rx ry rw rh] L --> S[get_vlc_scale: sx sy] S --> P2[Physical rect: prx pry prw prh] P2 --> C[GetWindowRect current: cx cy cw ch] C --> D{abs diff > tolerance?} D -->|No| SKIP[Skip resize] D -->|Yes| MOVE[SetWindowPos] MOVE --> CHECK[Next enforce loop]
  • 文件要寫清楚： 所有 Win32 比對以 Physical pixel 為準。
  • 文件要寫清楚： 位置容差與尺寸容差分開，避免無限 resize。
  • 文件要寫清楚： WebView Host 必須採用 Per-Monitor DPI aware。
