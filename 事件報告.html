輪播程式異常事件報告

日期： 2026年02月05日

事件類型： 系統崩潰 (Crash) / 網頁渲染錯誤 / 無法正常關閉

1. 問題描述

程式執行過程中，雖然主視窗 (Player) 保持開啟，但內容網頁載入緩慢、卡頓，或出現白畫面。嘗試關閉程式時，會觸發 Watchdog 機制導致程式無限重啟，無法透過 UI 正常退出。

關鍵錯誤代碼 (Event Viewer)

Faulting application name: QtWebEngineProcess.exe Faulting module name: KERNELBASE.dll Exception code: 0xe0000008 (Kernel Exception) Exception code: 0xc0000005 (Access Violation)

分析：

  • 0xc0000005：記憶體存取違規。在 QtWebEngine 中通常指向 GPU 驅動程式與 Chromium 渲染引擎的記憶體衝突。
  • 0xe0000008：無效的 Handle 或 Kernel 異常。在 Windows 環境下，這經常是因為 Renderer Code Integrity (Windows 安全機制) 認為渲染程序不安全（可能因防毒軟體掛勾 DLL）而強制終止它，導致網頁反覆崩潰與重啟（卡頓的主因）。

2. 除錯與版本迭代歷程

版本策略 設定內容 測試結果 結論
初期版本 (Balanced) 啟用 GPU 加速
禁用 Shader Cache		 失敗
出現 0xe0000008

終極安全模式 (CPU Only) 禁用 GPU
禁用 OpenGL
禁用 Code Integrity		 目前採用
穩定性最高		 雖然犧牲了 GPU 渲染效能（頁面載入可能稍慢），但根治了程序崩潰問題，確保能長時間掛機不白屏。

3. 最終解決方案 (Code Changes)

A. 啟動參數調整 (player.py)

採用「終極安全模式」，強制使用 CPU 渲染並關閉所有可能導致崩潰的實驗性功能。

# ULTIMATE SAFE MODE os.environ["QTWEBENGINE_CHROMIUM_FLAGS"] = ( "--disable-gpu " # 禁用顯示卡加速 (根治 0xc0000005) "--disable-opengl " # 禁用 OpenGL "--disable-gpu-compositing " # 禁用 GPU 合成 "--no-sandbox " # 降低權限隔離導致的錯誤 "--disable-features=RendererCodeIntegrity,FlashDeprecationWarning " #根治 0xe0000008 "--disable-site-isolation-trials " # 減少記憶體隔離崩潰 "--process-per-site " # 記憶體優化 (共用程序) "--check-for-update-interval=31536000" )

B. 修正「無法關閉」的 Bug

原本程式由 run_player.bat (Watchdog) 監控，程式關閉後會被自動重啟。修復後，在使用者點擊「結束播放」時，會主動尋找並殺掉父程序 (cmd.exe)。

def force_quit(self): """ User manually requested exit. We must KILL the parent watchdog (cmd.exe) to prevent it from restarting us. """ parent = psutil.Process(os.getpid()).parent() if parent and ("cmd" in parent.name() or "powershell" in parent.name()): parent.kill() # 殺掉監控腳本 QApplication.instance().quit()

4. 後續觀察建議

  • 效能監控： 由於改用 CPU 渲染，請觀察長時間播放 3D 或複雜網頁時 CPU 使用率是否過高（雖然比崩潰好）。
  • 記憶體洩漏： 已加入 --process-per-site 優化，但若長期掛機 (24h+) 仍有變慢跡象，需檢查 Windows 工作管理員的 RAM 使用量。
